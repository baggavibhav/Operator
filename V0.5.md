# V0.5 — reliable persistent local assistant

V0.5 folds the Windows/macOS V0.4 field-test findings into the next assistant slice instead of stacking features on brittle planning.

## Reliability contracts

- Common filesystem intents compile deterministically: selected-file info, largest-file ranking, and grounded extension move/copy flows.
- Read-only user goals cannot acquire write tools during model planning or recovery.
- Desktop selection is initial trusted context, not a fake `$steps.0` execution result.
- Explicit source folders such as Desktop/Downloads/Documents are grounded before planning.
- File extensions such as PNG/PDF/TXT are derived from natural language for deterministic discovery.

## Evidence-driven web agent

The web worker remains read-only and bounded, but completion is now owned by the orchestrator rather than the language model.

For research/summarization/current-information goals, a final answer is blocked until at least one public result has been opened and read. The model receives the current local date/time, should retry/broaden weak searches, and is instructed to prefer primary sources. Final research results retain opened source titles/URLs and optional follow-up suggestions.

## Persistent-assistant UX

- Task state remains durable in SQLite across restarts.
- The desktop worker exposes recent task history.
- The V0.5 desktop shell adds a Task History view from the tray.
- When the chat is hidden, completion, clarification, and failure events can surface through native tray notifications.
- The companion remains state-driven: idle/listening/thinking/working/approval/done/error animation reflects runtime state rather than decorative randomness.
- Stop/cancel remains cooperative at safe tool boundaries.
- Windows and macOS bootstrap scripts identify the V0.5 development build and use Phi-4 Mini consistently.

## Architecture boundary

The companion and desktop shell are clients of the persistent orchestrator, not the agent brain. This keeps the runtime suitable for future interfaces such as voice or a securely paired mobile companion without creating separate agents per device.

V0.5 does **not** grant arbitrary shell execution, generic click/type computer control, authenticated browser actions, purchases, email sending, or unrestricted network access. Those capabilities require separate typed tool adapters and explicit permission design rather than model-generated commands.

## Field-test gates before merge

1. Create `ImagesTest` inside `OperatorTest` and move Desktop PNG files into it.
2. Find the five largest Desktop files and report names/sizes without any write proposal.
3. With one Explorer/Finder file selected, answer `Tell me what file I have selected.` without step-reference errors.
4. Web research must search, open/read evidence, then synthesize with sources.
5. Clarification state must survive restart and resume correctly.
6. Stop/cancel must remain cooperative and safe around writes.
7. Task History must show durable recent tasks after relaunch.
8. Hidden-chat completion/clarification notifications must work on Windows and macOS where the tray supports them.
9. Windows and macOS bootstrap + companion launch must both pass field testing.
