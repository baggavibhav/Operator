# V0.4 development slice — context + read-only web

V0.4 builds on the validated V0.3.2 persistent orchestrator. This branch adds two capabilities without giving the model direct OS or browser authority.

## Desktop context

At the start of a new task the desktop adapter may capture:

- active application
- foreground window title
- current File Explorer / Finder folder
- selected files

The snapshot is stored in durable task context. Paths are revalidated through the existing filesystem sandbox before they can become authoritative sources or destinations.

This enables requests such as `Move these PDFs into OperatorTest` when the user has selected the relevant PDFs in Explorer/Finder. The selected files are authoritative; a model-proposed conflicting source list is overwritten by orchestrator state.

Windows uses fixed Win32 APIs plus a fixed PowerShell/Shell.Application query for the foreground Explorer window. macOS uses a fixed AppleScript query for Finder/front-app context. These commands are not generated by the model.

## Read-only web worker

New tools:

- `web_search(query, limit=5)`
- `web_open(url, max_chars=null)`

The first web slice is intentionally read-only. It does not support authentication, form submission, downloads, purchases, email, arbitrary clicks, or generic browser control.

Security controls include:

- HTTP/HTTPS only
- reject credential-bearing URLs
- DNS resolution before requests
- block loopback, private, link-local, multicast, reserved, and unspecified network destinations
- validate redirect targets with the same policy
- response-size/content-type limits
- `web_search` cannot reference prior tool output
- `web_open` may follow only a URL returned by a prior web step; filesystem/tool content cannot be sent to the network

This specifically blocks flows such as `read_text -> web_open($steps.0.content)`.

## UX cleanup

- denied writes now become `cancelled` instead of `failed`
- zero-result moves/copies get a human message instead of `Moved 0 file(s)`
- task status can show captured desktop context

## Validation

The local development tree passes 50 automated tests and Python compilation. New coverage includes desktop selected-file grounding, authoritative selected sources, web risk classification, SSRF/private-network rejection, mocked search/page extraction, exfiltration rejection, safe web-result chaining, cancellation state, and zero-result UX.

Live Windows/macOS context capture and live public search are still field tests and must pass before V0.4 is merged to `main`.
